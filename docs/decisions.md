# 決めたことと理由

新しい決定は上に足す。理由も一緒に書く（あとで「なぜこうしたか」が分かるように）。

## 2026-10-05
- **チャットは1タスク＝1チャット。記憶はリポジトリに置く。**
  理由：長いチャットは毎回の消費が大きい。vision / roadmap / decisions / BACKLOG を読めば、新しいチャットでも続きから作業できる。
- **今はプランを上げない（Maxは保留）。**
  理由：容量が減る主な原因は会話の長さ。チャットを分ければ足りる可能性が高い。本数を作る段階になったら再検討。
- **見た目の質は、モデル（AI）を変えても上がらない。**
  理由：ひざがない、顔が1種類などは、箱をコードで組む作り方の限界。直すには素体モデルとパーツ、仕組みの改善が要る。
- **キャラの作り込みは、家族以外の反応を見てから。**
  理由：価値が確かめられる前に、キャラに時間とお金をかけない。
- **撮影後に本物の写真へ切り替える。日付はフィルムカメラ風のオレンジ。**
  理由：「これがあの日の写真になる」という答え合わせが、一番の見せ場。本物の写真は本人に渡す動画にだけ入れ、リポジトリには入れない。
- **人種別モデルは作らない。共通の体＋ダイヤル＋パーツにする。**
  理由：本人らしさは人種では決まらない。当てはまらない人が出る。人種の判定はリスクが大きい。少ない部品で幅広く対応できる。
- **GLBモデルは使える。ただしライセンスを確認し、販売モデルは公開リポジトリに置かない。**
  ChatGPTが作ったGLBは、コードで箱を組んだもので、質は今と同じだった。質を上げるなら、人の手で作った素体（CC0の無料素材や外注）が必要。

## 2026-10-04
- **今の4シーン（valencia / hemisferic / iceland / reykjavik.html）は延命しない。凍結して見本として残す。**
  理由：1ファイルに全部書かれていて、キャラや背景がデータになっていない。時間割もない。Memory Movie は新しい仕組み（`movie/`）で作る。
- **台本データ（Scene Definition）で動かす。AIは「何をするか」、プログラムは「どこで・何秒に」。**
  理由：AIは座標や秒数が苦手。45秒ちょうどに揃えるのはプログラムが保証する。
- **同じ秒数なら毎回同じ映像になる作り（決定的）にする。**
  理由：巻き戻し・録画・修正の確認ができる。
- **当面は PS1 風の箱キャラで検証する。**
  理由：ユーザーが一番気に入っている絵柄で、資産がある。コードで「本物っぽい人」を作る試作（N64風・FF7風）は、何度作っても「何か違う」になった。
- **開発はブラウザとクラウドだけで行う（Chromebook前提）。** Blenderなどのパソコン用ソフトに頼らない。
- **写真はリポジトリに入れない。** 公開ページ（GitHub Pages）に人物のシーンを載せるのは、写っている全員の了承があるときだけ。
  そのため `movie/` は `_config.yml` で公開ページから外している。
